# 设备识别改为“有界候选 + 模型在候选内选择”

状态：implemented
类型：feature
Owner：backend/package/yuxi/knowledge/device_selection.py

> 消费方：`fault_trace/workflow.py`、`maintenance_plan/tool.py`、`device_prediction/tool.py` 的设备定位；召回增强落在各自的图谱适配器与 `device_index.py`。

## 问题

三个知识智能体的意图识别都有模型参与，但模型只看到用户原文（重识别时加上一轮结果与补充），看不到图谱里的真实设备名、同名设备与层级路径；设备匹配完全靠确定性规则。实测失败：

- `110kV银开线`、`35kV联络一线`：图谱名是不带电压前缀的 `银开线` / `联络一线`，旧 `find_devices` 精确/包含都匹配不到。
- `#1开闭所检修`：规则只把 `#1开闭所` 当作位置线索与设备类型，按路径召回被其下设备和 200 行上限淹没。
- `110kV变电站岭开线进线间隔_1101 隔离开关…`：设备名被截成 `变电站岭开线`，候选 0 条。
- 同名设备（`991SVG柜` 3 个、`910-1隔离柜` 3 个）只能靠用户猜，模型没有机会区分。

不能把 3002 台设备全量放进提示词（token、延迟、数据漂移不可控），也不能让模型直接生成设备名或台账 ID（会编造、绕过图谱事实）。

## 决策

1. **两段式**：意图字段 → 确定性召回阶梯 → 有界候选（默认 ≤24）→ 模型在候选内选择。
2. **召回阶梯**（按顺序、每级独立上限）：L0 名称精确与写法变体（去电压前缀、`N号`→`#N`/`N#`/`N`）；L1 名称/显示名包含；L2 名称词元（字母数字段与中文二元组）；L3 设备类型 + 电压/位置约束；L4 设备名索引（归一化精确/前缀/包含/词元覆盖/编辑相似）。
3. **模型只选不造**：模型输出 `{"device_id": "<候选 id 或 null>"}`；目标不在候选时返回 null，禁止选“最接近的”；清单外 id、非法 JSON、超时或模型不可用一律回退规则结果，不阻断主链路。
4. **人工确认不变**：处置方案每次弹设备确认卡片（上一轮已定）；故障溯源保留确认卡片；设备预测维护在候选 >1 时弹卡片。故障溯源的多候选选中后会收敛为一台设备继续（仍展示确认卡片）；处置方案与设备预测维护的模型选择只决定推荐位（选项 label 末尾“（推荐）”）与排序，不替代用户确认。
5. **设备名索引**：一次读取 kg5 `设备实例`（当前 3002 条）构建进程内索引，按 `{uri}|{graph}` 缓存，TTL 600 秒；只用于召回，不产生新的设备事实，也不参与授权。构建失败回退现有名称查询。
6. **可观察与兜底**：选择状态写入思考步骤 `device_selection`（`state`、候选数、`selected_id`）；三个模块在召回为空时写 `warning` 日志（含原文意图字段），仍返回既有固定文案，由用户补充或补数据。
7. **同时修复上一轮 Review 的问题**：处置方案关闭设备/场景卡片按取消返回固定文案（不再把 `reject` 当补充文本反复弹窗）；线路正则不再吞“母线”、`N号主变…电流互感器` 保留完整设备名；设备 id 多类型按 fail-closed 返回 `device_type_missing`，台账 ID 回退只在设备没有 id 时使用并跳过占位值；处置方案报告增加“设备位置”行；删除不可达的防御分支。

## 替代方案

- **把全量台账/图谱塞进提示词**：3002 台设备的 token、延迟与数据漂移不可控；放弃。
- **让模型直接输出设备名或台账 ID**：会编造图谱里不存在的设备并绕过图谱校验；放弃。
- **只在前端做模糊匹配**：图谱查询与证据读取在后端，前端匹配不影响实际查询；放弃。
- **召回为空时让模型猜最接近的设备**：选错设备会让现象、原因与方案全部按错误设备生成，且用户难以发现；放弃。

## 后果

- 三个模块的候选召回不再受“用户写法与图谱名不一致”和 200 行上限限制；模型可以在同名/同前缀设备间给出推荐。
- 模型不可用、超时、返回非法 JSON 或清单外 id 时，行为与改动前一致（规则排序；处置方案仍弹卡片）。
- 索引最多滞后 10 分钟；kg5 重新导入后最迟 TTL 生效，不写持久化。
- 设备预测维护在候选 >1 时仍弹卡片，不做“模型高置信直接采用”。
- 仍然找不到设备时只返回固定文案并记录 miss，不猜设备；kg5 数据问题（2006 台设备缺少 `属于` 边、301 台共用 `补充数据` 台账 ID）没有被代码消除，需要数据侧补齐。

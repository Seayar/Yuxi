# 处置方案按 kg5 识别设备：目标设备与层级路径分离

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/knowledge/maintenance_plan/graph_plan.py

> 消费方：`maintenance_plan/intent.py` 的设备名抽取、`maintenance_plan/tool.py` 的候选选择与卡片、`maintenance_plan/contracts.py` 的候选展示。

## 问题

两个真实问法在 kg5 上识别不到目标设备：

- `#1开闭所检修，需确定监护与人员配置的方案。`：规则抽取只把 `#1开闭所` 当作位置线索与设备类型（`device_name` 为空），检索按位置关键词召回该开闭所下的低压柜/PLC 柜；kg5 里 `#1开闭所` 本身是设备（`属于 开闭所`），但按路径关键词召回时被 200 行上限挤掉，候选里一直没有它，用户反复选择也选不对。
- `110kV变电站岭开线进线间隔_1101 隔离开关触头氧化、轻微烧蚀，需处理方案`：线路正则把设备名截成 `变电站岭开线`，候选 0 条。kg5 中真实设备是 `岭开线进线间隔_1101`，且 `属于 隔离开关`，类型与用户描述一致，纯粹是名字抽取截断。

另外，设备候选的 `label()` 把“名称（类型，电压）— 完整层级路径”拼成一段，卡片上的目标设备显示成一长串，用户无法快速确认选的是哪台设备。

## 决策

- 设备名抽取新增 `间隔_NNNN` 的整段模式；位置前缀（`110kV变电站` 等）只在线路/间隔两个模式命中后剥离。其它设备名保持原话（`#62箱变13馈出柜`、`#3开闭所3k18断路器` 的抽取不变）。
- 检索对 `device_name` 与 `location_hint` 各做一次设备名称精确查询，避免目标设备被其下设备的路径命中与 200 行上限淹没；有 `device_name` 时，位置线索不参与精确加分（位置只表示“在哪儿”，不能反客为主当目标）。
- `_pick_device` 每次都用卡片让用户确认目标设备，唯一候选或名称正好命中也不自动采用；用户可在卡片上改选候选或自行填写设备名。图谱存在同名/同前缀设备，自动确认选错后场景、分支与人员都会按错误设备生成。
- 候选 `label()` 只保留“名称（类型，电压）”；层级路径改由 `location()` 作为选项 `description` 展示，同名设备仍可区分。

## 替代方案

- **把 `#N开闭所` 加进设备名模式**：会把位置本身当设备名，破坏“更换#3开闭所3k18断路器”的设备名抽取（`test_device_name_is_not_the_location_hint` 已守护该语义），放弃。
- **全局剥离位置前缀**：会把 `#62箱变13馈出柜` 截成 `13馈出柜`，放弃；改为只在线路/间隔模式剥离。
- **按位置线索召回全部下级设备让用户选**：目标不明确，且 200 行上限会漏掉目标本身，放弃。
- **让目标设备固定显示完整路径**：同名设备需要区分，但路径应作为次要说明而不是标题；改为 label + description 分工。

## 后果

- `#1开闭所检修` 在 kg5 上召回 `#1开闭所（开闭所，10kV）` 作为首个候选，由用户在卡片上确认；`110kV变电站岭开线进线间隔_1101 隔离开关…` 召回唯一的 `岭开线进线间隔_1101（隔离开关，110kV）`，同样需要用户确认。
- 既有台账写法（`#3开闭所3k18断路器`、`#62箱变13馈出柜`、`991SVG开关`）的抽取结果不变。
- 卡片选项标题变短，长路径作为 `description` 展示；报告中的目标设备同步变短。
- 没有设备名且位置线索不是某台设备名时，仍按位置召回并弹选择卡片，不自动猜设备。

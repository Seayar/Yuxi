# 电力规范结构化证据边界

状态：implemented
类型：feature
Owner：backend/package/yuxi/knowledge/power_spec/retrieval.py

## 问题

知识库 chunk 中可能包含完整规范字段，但适配器有时将整段 chunk 当作条款正文，或将 OCR 表格数值误绑定为条款编号和标题。最终 assistant 又会基于不稳定的 Tool 结果自行重组格式，导致条款、标题、正文和引用无法稳定对应。

## 决策

规范卡片的事实字段由程序从知识库原文、规范派生元数据和检索分数确定性生成。适配器优先使用已解析的条款正文和元数据；缺少标题时只从同一 chunk 中提取可验证的章节标题；数值型 OCR 表格标题不作为条款标题，无法确认的字段保持为空，不由模型猜测。大模型只接收结构化证据并按固定 `answer_markdown` 输出，不重算相关度、页码、条款编号、替代规范或引用。

同一文件的不同章节以独立 `document_id#clause_no` 保留，召回候选扩大后最多选择 5 个不同条款。历史派生数据在命中时惰性重建，缺少条款正文或包含 `0.x` 伪章节时重新解析。

## 替代方案

1. 让大模型直接从 chunk 自由提取所有字段：实现快，但会引入无法验证的条款、页码和引用，因此拒绝。
2. 只依赖现有 OCR 解析：不会产生模型幻觉，但无法处理 OCR 标题缺失和历史错误派生数据，因此不足。
3. 采用程序确定性解析为主、受限模型抽取为后备：当前实现先完成程序主路径；无法确认的事实不进入卡片，后备模型抽取另行评估。

## 后果

卡片字段和引用稳定、可审计；没有页码或标题证据时会显示未提供或章节编号，而不是补造内容。历史文件首次命中可能触发一次惰性派生提取。最终聊天文本仍由模型发布，但其可引用事实来自程序生成的固定 Tool 结果；正式前端仍应直接渲染 `spec_results` 以彻底避免模型改写卡片。

# 电力规范多问题意图拆分与逐题回答

状态：archived
类型：feature
Owner：docs/develop-guides/decisions/implemented/2026-11-12-power-spec-remove-multi-question-split.md

本记录记录的能力已被 [移除电力规范检索的多问题拆分与逐题回答](../implemented/2026-11-12-power-spec-remove-multi-question-split.md) 完全移除，仅保留为历史背景。

## 问题

意图识别提示词要求模型只输出一个完整问题，用户一次提出“问题1...问题2...”时，模型把多个问题合并成一个 `question`，`intent`、`device_type`、`voltage_level` 只保留第一个或合并后的口径。确认卡片只能展示一个计划，检索只按合并问题召回，整理子智能体也只看到一个长问题。多跳题的第二问因此经常缺少独立召回与结论，答案级准确率低。

## 决策

1. `PowerSpecIntentResult` 增加 `sub_questions`，提示词先判断问题数量：单问题输出顶层字段且 `sub_questions=[]`；多问题按原顺序输出每个子问题的 `question`、`intent`、设备、电压、维度和关键词，最多 6 项。模型只负责拆分和字段识别。
2. `PowerSpecQuery` 增加 `sub_queries`；显式“问题N./N.”的题干保留用户原句，模型返回的子问题文本按顺序替换为原句，避免“相差多少/如何计算”等多步要求被改写丢失。
3. 确认卡片逐条展示子问题；确认计划整体编码，恢复时重建全部 `sub_queries`。单问题路径保持原行为。
4. 检索路线依次加入模型拆出的子问题；图谱命中匹配也把子问题文本纳入精确/模糊匹配。组委会看到完整子问题列表，并在 `answers` 中为每个子问题各给一条仅依据原文的简短结论；最终答案在卡片前渲染 `### 问题回答` 摘要。
5. 图谱证据按 `graph_group` 轮转排列，避免第一组条款占满名额截断后续子问题；带表号的引用优先匹配真正的表题条款，而不是“见表 N”的交叉引用。
6. 最终卡片仍按原四字段渲染；多问题答案摘要是附加在卡片前的结论，不改变卡片正文来自知识库原文的规则。

## 替代方案

- **只按正则拆分检索路线**：已有实现，能增加召回，但确认卡片仍是一个计划，每个子问题没有独立设备/电压/维度，第二问的意图无法进入下游。
- **每个子问题单独调用一次意图模型**：字段更独立，但串行模型调用增加延迟和失败面，且拆分本身仍需要一个前置判断。
- **让模型继续合并成一个问题**：当前缺陷，第二问容易在长问题里被稀释。
- **直接把图谱答案节点作为多问题最终答案**：能提高测评通过率，但会让基准 Gold Answer 绕过知识库卡片，属于基准过拟合取舍。

## 后果

- 多问题输入会增加意图输出、整理和合并的 token 与时延；子问题上限 6，超出的问题不进入独立路线。
- 子问题保留原句后，模型必须处理用户原话中的条件链和计算要求；整理者仍可能回答“未找到依据”，因此图谱映射不完整的题不会自动变正确。
- 逐题 `answers` 是模型生成的简短结论，仍需审查子智能体核对；最终卡片正文仍来自知识库。
- 单问题输入、既有确认重放和固定卡片回退路径不变。

## 验证

- 单元测试：`docker compose exec -T api python -m pytest test/unit/knowledge -k power_spec -q` 共 250 项通过，覆盖意图多问题解析、原句保留（`test_explicit_subquestion_stems_are_kept_verbatim` 断言显式编号题干与“相差多少米”计算尾句按原句进入 sub_queries）、确认卡片与计划回放、检索路线、图谱分组轮转、表题优先、整理者多问题提示、逐题 answers 解析与最终渲染。
- 真实模型意图：`MULTI_02`、`MULTI_04`、`MULTI_05` 均拆出 2 个子问题，`MULTI_04` 的第二问保留“两处安全距离相差多少米”。
- 真实多跳复跑（`local:Qwen3.6-35B-A3B-w8a8`，6 张证据上限，答案级裁判）：`MULTI_05` 1.0，首卡为 `DL/T 596-2021 15.1.6` 的表 48；`MULTI_04` 1.0，首卡为 `DL/T 408-2023 5.3.1.3` 的表 1，答案 0.35 m 与 0.65 m；`MULTI_02` 0.0，第二问仍答“未在给定条款中找到依据”。
- `MULTI_02` 的失败原因在图谱映射与长表格召回，而不在意图：该题图谱种子只连到 `DL/T 596-2021 4.5` 和 `DL/T 393-2021 4.6.1`，第二问需要的 DGA/糠醛超过 4 mg/L 判据实际位于 `DL/T 596-2021 6.1` 的表 5，测评集的“标准依据”没有给出这一条。该条款正文约 7000 字符，reranker 只读取前 600 字符，判据行落在截断之外，常规召回无法稳定把它送入候选；图谱映射补齐该条款后才能绕过这一限制并重跑该题。
